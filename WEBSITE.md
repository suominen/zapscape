# Website plan — `https://kimmo.cloud/zapscape/`

Publish the Zapscape tracker as a single-page static site, generated by
**Hugo** locally and rsync'd to a personal nginx server (`haig`).  The build
infrastructure mirrors the sibling januscape / itscape / ovswrap trackers;
only the content and a few config strings differ.

## Architecture

- **Source repo:** `github.com/suominen/zapscape` (this repo).
- **Generator:** Hugo extended, ≥ 0.146.0.  Run locally; nothing built in
  CI.
- **Source layout:** Hugo project under `site/`.  The tracker is a single
  page at `site/content/_index.md`.
- **Theme:** PaperMod, integrated as a Hugo Module (no submodule).
- **Dev environment:** Nix flake (`flake.nix`) provides hugo + go + git +
  resvg (for `make banner`) + curl/libarchive/zstd (the auto-update agent's
  RPM-unpacking tools).  Auto-activates via `.envrc` if direnv is installed.
- **Build:** `make build` → `hugo --minify --gc --cleanDestinationDir`,
  output in `site/public/`.
- **Publish:** `make dist` → `rsync -avz --delete site/public/` →
  `haig:/zapscape/`.
- **Web server:** existing nginx vhost on `kimmo.cloud` serves
  `htdocs/zapscape/` directly at the URL path `/zapscape/`.

## Naming — nickname slug (CVE assigned)

The bug has a marketable name (**Zapscape**, from the [PoC][poc]) *and* a
CVE (**CVE-2026-64561**) from the outset.  Following the sibling precedent —
which runs both ways (pintheft and cifswitch kept nicknames; Dirty Frag was
renamed to `/CVE-2026-43284/`) — the site uses the **nickname** as its slug
everywhere, with the CVE carried in the tracker body, Summary, and title:

- repo: `~/src/zapscape`, `github.com/suominen/zapscape`
- Go module path: `github.com/suominen/zapscape/site`
- URL: `https://kimmo.cloud/zapscape/`
- systemd units: `zapscape-tracker-update.{service,timer}`

No redirect is needed; the slug never moves.

## Cross-reference — the `-scape` KVM-escape family

Zapscape is the third KVM guest-to-host escape disclosed by Hyunwoo Kim
(`@v4bel`), after the July 2026 pair **Januscape (CVE-2026-53359)** (x86
shadow-MMU role confusion) and **ITScape (CVE-2026-46316)** (arm64 vGIC-ITS).
Like Januscape it is x86-only and lives in the shadow MMU, but the mechanism
is different — a check-ordering bug that populates an *invalidated* root
rather than a role/`direct` confusion — so it is a separate CVE and tracker,
not an update to Januscape.  The Summary "Related" row and the References
table cross-link both prior trackers (`~/src/januscape` /
<https://kimmo.cloud/januscape/> and `~/src/itscape` /
<https://kimmo.cloud/itscape/>); both are retired.

## Tracker content

- One kernel bug, **single verdict axis**: the `2abd5287f083` fix
  (v7.2-rc5) is the only thing that flips a row.  There is no userspace
  reachability gate (unlike cifswitch's cifs-utils second axis).
- `/dev/kvm` exposure (world-accessible on EL8+ vs `root:kvm` on
  Debian/NixOS) and nested-virt defaults decide *who* can reach an
  unpatched kernel; they are recorded in prose, **not** as columns, and —
  unlike ipv6_frag_escape's `init_on_alloc` — they do **not** downgrade a
  verdict (both vectors are full compromises, so affected-unpatched is
  `:x:`).
- **Patch status** uses a single **combined table** for upstream and
  distros (`Distribution | Release | Current kernel | First fixed | Fixed
  since | Status`): the upstream kernel is the first `Linux kernel` group;
  opt-in kernels (bullseye `linux-6.1`, PVE opt-in series) are their own
  rows, while the niche EL `kernel-rt` variant stays prose-only; per-distro
  `###` headings are retained only where there is an audience-relevant
  note.  *Current kernel* is live; *First fixed* / *Fixed since* are
  sticky.  In the browser the Distribution column renders as full-width
  group heading rows, and the column header and group headings are sticky.
  This is the merged-table layout piloted in ghostlock and folded into
  `~/src/cve-tracker-template`.
- The bug reaches back to **v5.9** (2020, the `f95eec9bed76` invariant);
  every tracked distribution kernel is in-window, so there are **no** "not
  affected" rows here.  Unusually for this family the fix has so far been
  backported only to the **6.6, 6.12, 6.18, and 7.1** stable lines — the
  **6.1, 5.15, and 5.10** LTS lines carry no fix yet, so their rows (and the
  distros riding them) seed `:x:`.  Rows seed `:x:` unless a backport is
  confirmed; EL and Proxmox rows seed `:grey_question:` pending advisory
  verification.  No unconfirmed "fixed" claims.
- **No rows for series already dead when the tracker was seeded.**  A
  release, stream, or kernel series whose updates ended before the
  disclosure and that never carried the fix gets no row — a permanent
  `:x:` that can never flip is dead weight — so the EOL upstream **7.0.y**
  line (7.0.14, 2026-06-27) and the superseded Proxmox **6.17 / 6.14 /
  6.11** series are one-sentence prose notes, not rows.  A series that
  died already *fixed* would keep its row; see the rule in `CLAUDE.md`
  (and `cve-tracker-template`).
- Social/OpenGraph banner — `site/assets/zapscape-tracker.svg` rasterised
  to `site/static/zapscape-tracker.png` by `make banner` (resvg), wired
  into the `cover:` front-matter.

## Steps

### 1. Hugo project — cloned from januscape

The Hugo skeleton, theme integration, PaperMod overrides, CSS, i18n, and
the KVM-tree auto-update plumbing were copied wholesale from the januscape
tracker (the closest KVM/x86 sibling) on 2026-08-07.  Only `baseURL`,
`title`, the Go module path, the banner, the systemd unit names, the timer
slot, and the rsync destination were retargeted, and the content +
CLAUDE.md + auto-update prompt were rewritten for this bug.  The auto-update
agent already reads the KVM tree (`~/src/linux/kvm`) inherited from
januscape.

### 2. Publish

- [ ] First `make build` and inspect `site/public/` locally.
- [ ] First `make dist` to push to `haig` — `htdocs/zapscape/` created
      (let rsync make it).
- [ ] Verify the site renders at `https://kimmo.cloud/zapscape/`,
      including the RSS feed and OG metadata.

### 3. Automated maintenance

- [ ] `git worktree add -b auto-update ~/src/auto-update/zapscape main`
- [ ] Install and enable
      `systemd/zapscape-tracker-update.{service,timer}` as user units
      (see CLAUDE.md for the exact `ln -sr` + `systemctl --user` recipe).
- [ ] Confirm the timer slot `05,17:20` does not collide with the live
      siblings (ovswrap `:05`, CVE-2026-42533 `:35`).

## Decisions

- **Hosting:** own nginx on `haig`, *not* GitHub Pages.  Same as the
  sibling trackers.
- **URL:** `https://kimmo.cloud/zapscape/` (nickname slug; see "Naming").
- **Theme integration:** Hugo Modules; theme PaperMod.
- **Canonical source:** `site/content/_index.md`.
- **Automated maintenance:** a user-level systemd timer
  (`systemd/zapscape-tracker-update.timer`, twice daily) runs
  `scripts/auto-update`, which merges `origin/main` into a dedicated
  long-lived `auto-update` branch in a separate worktree and hands off to
  headless Claude with `scripts/auto-update-prompt.txt`.  The agent only
  commits onto `auto-update` — it does not push or open PRs.  Merges of
  `auto-update` into `main` are done manually.  The wrapper prints a
  `Zapscape tracker auto-update starting …` banner as its first output
  line so aggregated syslog can tell the trackers apart.

## Risks & gotchas

- **Anchor drift.** Hugo/Goldmark's heading slugger differs from GitHub's
  for headings with em dashes, parens, plus signs, or slashes.  Pin brittle
  headings with `### Heading {#stable-id}` if external bookmarks need to
  survive renames.
- **Subpath baseURL.** `baseURL = "https://kimmo.cloud/zapscape/"` must
  include the trailing slash and the path component.
- **`.cleanDestinationDir`** wipes `site/public/` before each build.
- **rsync `--delete`** removes server-side files not present in the build
  output.  Don't store unrelated content under `htdocs/zapscape/`.
- **Client-side table tweaks.** `layouts/partials/extend_footer.html`
  rewrites tables in the browser: in the `.distros` table it replaces
  the Distribution column with full-width group heading rows (one per
  distribution; Markdown can't express colspan, so the source keeps a
  plain column); other tables get consecutive duplicate first-column
  cells collapsed via `rowSpan`; status-emoji cells are tagged so
  `custom.css` can hang-indent them.  With JavaScript disabled the
  tweaks are skipped — the table still renders correctly, with the
  Distribution column visible and repeated.

## Social banner

The OpenGraph / social-preview image is generated from an SVG source:
`site/assets/zapscape-tracker.svg` (1200×630) is rasterised to
`site/static/zapscape-tracker.png` by `make banner`, which runs `resvg`.
The PNG is committed so ordinary `make build` / `make dist` runs need no
rasteriser.  `resvg` needs the Roboto fonts (`fonts-roboto-unhinted` on
Debian) — without them it silently drops the SVG's sans-serif text.
