Zapscape (CVE-2026-64561) is a KVM/x86 guest-to-host escape in the Linux
kernel: a stale-root check-ordering bug in the shadow-MMU page-fault
handlers. is_page_fault_stale() ran before make_mmu_pages_available(), so
when reclaiming shadow pages zaps the vCPU's in-use root (marking it
invalid), the handler goes on to map into that invalid root; child shadow
pages inherit role.invalid and land on the list of active MMU pages,
violating the invariant that invalid pages are never on it: memory
corruption / a use-after-free the PoC turns into host code execution. A
hostile guest can escape to host root; where /dev/kvm is world-accessible
(the EL8+ default) an unprivileged local user can trigger it too. The
canonical fix is 2abd5287f083 (KVM: x86: Check for invalid/obsolete root
*after* making MMU pages available), first released in v7.2-rc5. The bug
became exploitable with f95eec9bed76 in v5.9 (2020), so kernels from 5.9
through 7.1 are in-window. It is x86-only; arm64 KVM is a different MMU and
is not affected.

Working-tree hygiene: stream a fetch through a pipe — `curl -fsSL <url> |
grep …` — when one pass over the data is enough. If you genuinely need a
scratch file, save it in the worktree under a `.scratch-` prefix (e.g.
`.scratch-advisories.json`), work on it there, and `rm` it before you
commit — never `git add` a scratch file. Don't use /tmp: Bash file reads
are confined to the worktree, so a file there can be written but not read
back. The wrapper's `git clean -fd` sweeps forgotten scratch on the next
run, but the only thing you should leave behind is the edited tracker
(and its commit).
